# VocabMaster 잔여 개발 통합 요청문

> **용도:** 1차 개발 요청 이후 남은 작업을 빠짐없이 전달하는 최종 개발 요청서
>
> **기준 문서:** `docs/voca-design-v3.md`, `docs/development-request.md`, `docs/vocabmaster-storage-contract.md`
> **중요:** 이 문서는 “한 번에 전부 배포”하라는 뜻이 아니다. 아래 Gate 순서대로 작은 PR로 구현하고 각 Gate를 통과한 뒤 다음 단계로 진행한다.

## 1. 요청 목적

1차에서 Source/Item/Progress 기반을 안정화한 뒤, 사용자가 매일 바로 학습할 수 있는 SRS 루프부터 AI 연상, 예문, 말하기, 회화, 통계와 저장소 확장까지 완성한다. 최종 결과는 “등록한 단어가 오늘 학습에 들어가고, 여러 방식으로 복습되며, 문장과 발화에서 사용되는” 하나의 연결된 경험이어야 한다.

## 2. 착수 전 필수 조건

다음 조건이 충족되지 않았다면 후속 기능을 시작하지 말고 1차 요청을 먼저 완료한다.

- 모든 콘텐츠가 안정적인 `itemId`를 가진다.
- Source 선택과 Mode 선택이 분리되어 있다.
- `errCount`, `sErrCount`, `toeicErrCount` 대신 Progress/StudyEvent를 사용한다.
- 숫자는 공통 selector에서만 계산한다.
- 기존 `vm-*` 백업과 v2 마이그레이션이 테스트된다.
- 단어 Source에서 문장 전용 모드가 실행되지 않는다.
- 저장과 UI가 `docs/vocabmaster-storage-contract.md` 계약을 따른다.

## 3. 전체 납품 범위

| Gate | 개발 범위 | 사용자에게 보이는 결과 |
|---|---|---|
| A | 오늘 학습 + 최소 SRS | 원탭으로 복습/신규 학습 |
| B | 적응형 연상 + 예문 | 어려운 단어에 기억 단서와 회화 예문 |
| C | 문맥 학습 연결 | 단어가 빈칸·받아쓰기·말하기로 이어짐 |
| D | STT/Whisper + 발음 피드백 | 브라우저 호환 말하기 학습 |
| E | AI 회화 + 종료 리포트 | 오늘 단어를 실제 대화에서 사용 |
| F | 기록·통계·접근성 | 신뢰할 수 있는 오늘/주간 지표 |
| G | IndexedDB·서버 준비 | 데이터 증가와 공개 배포에 대응 |

## 4. Gate A — 오늘 학습과 최소 SRS

### 4.1 평가와 간격

모든 복습 결과는 `Again / Hard / Good / Easy / Skip` 중 하나다.

| 평가 | 상태 변경 |
|---|---|
| Again | `lapses + 1`, streak 0, 세션 뒤쪽에 재삽입, 다음 due는 1일 이내 |
| Hard | 짧은 간격, ease 소폭 감소, 정답으로 기록 |
| Good | 기본 간격 증가, streak 증가 |
| Easy | Good보다 긴 간격, ease 소폭 증가 |
| Skip | 진도·정확도 변경 없음 |

정확한 계수는 별도 순수 함수로 두고 테스트에서 고정한다. 최소 ease는 1.3이다. 신규 항목은 당일 학습 단계 후 1일 복습으로 보내며, 시스템 시각이 아니라 사용자 시간대로 due를 계산한다.

### 4.2 오늘 큐

- 우선순위: overdue → due today → learning retry → new.
- 기본 상한: 복습 20개, 신규 5개. 설정에서 변경 가능하다.
- 소스가 겹쳐도 itemId 기준 한 번만 큐에 넣는다.
- 대기 항목이 상한을 넘으면 “추가 복습 N개”를 표시한다.
- “급한 복습만”, “신규 제외” 진입을 제공한다.
- 같은 입력과 날짜/seed에는 같은 큐가 만들어져 디버깅할 수 있어야 한다.
- Again 항목은 최대 재출제 횟수를 두어 무한 루프를 막는다.

### 4.3 세션 복구

활성 큐, 커서, 이미 생성한 이벤트 ID를 매 답변 후 저장한다. 새로고침하면 같은 문제부터 이어지고, 완료 이벤트가 중복 기록되지 않아야 한다. 날짜 변경 시 이어하기 또는 새 오늘 큐 시작을 명시적으로 선택시킨다.

### 4.4 UI

오늘 화면에 `오늘 복습`, `신규`, `예상 학습량`, `시작/이어하기`를 보여준다. 세션 중에는 현재/전체, 문제 유형, 답변, 피드백, 평가 버튼, 종료를 제공한다. 완료 화면에는 푼 항목, 정확도, Again 항목과 다음 복습 예정일을 표시한다.

### 4.5 Gate A 완료 기준

- 새로고침과 중복 클릭에도 StudyEvent가 한 번만 기록된다.
- 복습 상한과 신규 상한이 정확히 지켜진다.
- Source 중복 Item이 한 세션에 중복 출제되지 않는다.
- Skip/STT 실패가 오답 처리되지 않는다.
- due 순서와 평가별 다음 일정의 단위 테스트가 통과한다.

## 5. Gate B — 적응형 AI 연상과 예문

### 5.1 생성 정책

- 모든 1,140개 단어를 선생성하지 않는다.
- 신규 단어를 실제 학습할 때 짧은 회화 예문 1개와 대표 연상 1개를 생성한다.
- AI 키가 없거나 호출이 실패해도 기본 학습은 계속된다.
- `lapses >= 2`에서 추가 후보를 최대 2개 제안한다.
- 사용자는 선택, 좋아요/싫어요, 직접 수정, 재생성을 할 수 있다.
- 억지스러운 소리 연상은 `null`을 허용한다.

### 5.2 품질과 캐시

구조화된 응답을 스키마 검증한 뒤 저장한다. 캐시는 `itemId + promptVersion + model + contextHash`로 구분하고, 같은 요청을 중복 호출하지 않는다. 재생성은 사용자 수정본을 보존한다. 뜻이 다른 동형어의 캐시는 절대 공유하지 않는다.

예문은 짧고 자연스러운 일상 회화 문장이며 목표 뜻이 드러나야 한다. 잘못된 어원은 만들지 않고 불확실하면 생략한다. AI 결과는 HTML로 삽입하지 않는다.

### 5.3 Gate B 완료 기준

- 새로고침 후 선택·수정한 연상이 유지된다.
- API 실패가 학습 세션을 중단하지 않는다.
- 동일 캐시 요청은 네트워크 호출을 반복하지 않는다.
- 프롬프트/모델 버전 변경과 사용자 수정본 보존이 테스트된다.

## 6. Gate C — 단어에서 문장·문맥 학습으로 연결

- 승인된 AI 예문은 원 단어의 `exampleItemIds`로 연결한다.
- 사용자가 원할 때 예문을 sentence Item 및 별도 예문 Source에 등록한다.
- 자동 생성만으로 학습 항목을 무제한 늘리지 않는다. 등록 전 미리보기와 승인 절차를 둔다.
- 단어 학습 흐름을 인식(객관식) → 회상(뜻→영) → 문맥(빈칸/전체 문장)으로 확장한다.
- 오답은 같은 문제의 단순 반복보다 가능한 다른 호환 모드로 재출제한다.
- 단어 Progress와 예문 Progress는 별개로 기록하되 관계를 통해 통계에서 연결한다.

### Gate C 완료 기준

- 단어에서 해당 예문으로 이동하고 다시 원 단어를 확인할 수 있다.
- 예문 승인 전에는 신규/복습 숫자가 변하지 않는다.
- 문장 오답이 단어 오답을 임의로 증가시키지 않는다.

## 7. Gate D — 말하기와 Whisper

### 7.1 처리 흐름

```text
마이크 권한 확인
  → 브라우저 STT 시도
  → 미지원/실패 시 MediaRecorder 녹음
  → Whisper 전사
  → 사용자가 전사문 확인·수정
  → 규칙 기반 비교
  → 애매할 때만 AI 채점
  → 사용자 확정 후 StudyEvent 저장
```

- `saveOpenAIKey()` 같은 이름만 있는 버튼을 노출하지 않는다.
- 녹음 중/업로드 중/전사 중/확인 중/채점 중 상태를 구분한다.
- 권한 거부, 빈 녹음, 시간 초과, 네트워크 실패에 재시도와 텍스트 입력 대안을 제공한다.
- 녹음 파일은 전사 후 즉시 폐기하며 영구 저장하려면 별도 동의를 받는다.
- 브라우저에 API 키를 저장하는 개인용 모드에는 위험을 명시한다. 공개 배포에서는 서버 프록시 없이는 Whisper를 활성화하지 않는다.
- 단어 단위 차이는 피드백일 뿐 자동 발음 점수라고 과장하지 않는다.

### Gate D 완료 기준

- Chrome/Safari의 지원·미지원 경로가 모두 테스트된다.
- 전사 확인 전에는 오답 이벤트가 생기지 않는다.
- 취소/실패가 학습 정확도를 바꾸지 않는다.
- API 키 안내, 실제 저장 위치, 삭제 동작이 서로 일치한다.

## 8. Gate E — AI 회화와 리포트

### 8.1 MVP 순서

먼저 텍스트 회화를 구현해 타깃 유도와 교정 품질을 검증한다. 이후 Gate D의 음성 입출력을 연결한다. 실시간 API는 별도 검토 전 사용하지 않는다.

### 8.2 대화

- 카페, 여행, 직장, 스몰토크 시나리오와 난이도를 선택한다.
- 오늘 학습한 단어 3~5개를 타깃으로 삼되 억지로 강요하지 않는다.
- 답변은 짧게 유지하고 자연스러운 recast로 교정한다.
- 일반 대화 응답과 종료 분석 JSON은 별도 호출로 분리한다.
- 긴 대화는 앞부분을 요약하되 원문 보존 여부와 비용 한도를 정한다.

### 8.3 종료 리포트

사용한 타깃, 놓친 타깃, 교정 표현, 새 표현, 요약을 보여준다. 새 표현은 사용자가 개별 승인한 경우에만 Item/Enrollment로 저장한다. 타깃 사용 여부는 단순 부분 문자열이 아니라 정규화·문맥 검증을 거친다. 자동 판정은 사용자가 수정할 수 있다.

### Gate E 완료 기준

- 대화 실패 후 재시도해도 transcript가 중복되지 않는다.
- 종료 분석 실패 시 대화 기록은 보존되고 분석만 재시도할 수 있다.
- 승인하지 않은 표현은 카드나 Progress를 만들지 않는다.
- 회화 사용 한 번만으로 전체 단어를 “마스터” 처리하지 않는다.

## 9. Gate F — 기록, 통계, 접근성

### 9.1 지표 정의

- 오늘 풀이: 오늘 생성된 `correct !== null` StudyEvent 수.
- 오늘 정확도: 오늘의 정답 이벤트 / 정답+오답 이벤트.
- 오늘 복습: `dueAt`이 오늘 끝 이전이며 중지되지 않은 고유 Item 수.
- 신규: Progress가 없고 `newEligible`인 고유 Item 수.
- 마스터: 합의된 파생 규칙을 충족한 Item 수. 원본 level 값으로 저장하지 않는다.
- 스트릭: 사용자 시간대에서 학습 이벤트가 하나 이상 있는 연속 날짜.

음성, 문장, 회화 이벤트도 정의에 맞게 포함하되 Skip과 기술 실패는 제외한다. 주간 차트와 숙련도 분포는 같은 selector를 사용한다.

### 9.2 접근성

- 키보드만으로 모든 학습과 모달을 완료할 수 있어야 한다.
- 포커스 표시, 모달 포커스 트랩/복귀, 적절한 label과 live region을 제공한다.
- 색상만으로 정오답을 구분하지 않는다.
- `prefers-reduced-motion`과 모바일 터치 영역을 지원한다.
- 마이크 상태와 오류를 화면 낭독기가 이해할 수 있게 알린다.

### Gate F 완료 기준

- 같은 데이터에서 오늘/학습선택/기록 화면 숫자가 모두 같다.
- 자정, 시간대 변경, 빈 데이터, 전부 Skip인 날의 테스트가 통과한다.
- 핵심 학습 흐름의 키보드 및 모바일 수동 검증 기록이 있다.

## 10. Gate G — 저장 확장과 공개 배포 준비

### 10.1 IndexedDB

StudyEvent/회화 기록이 localStorage의 측정된 한계를 넘을 때만 `Repository`의 IndexedDB 구현을 추가한다. 마이그레이션 전 자동 백업, transaction, 실패 시 롤백, 계약 테스트를 제공한다. 기능 코드와 UI는 저장 구현 변경을 몰라야 한다.

### 10.2 서버 프록시

공개 배포 전에 AI 제공자 키를 브라우저에서 제거하고 서버리스 프록시로 이동한다. 인증, 요청 크기 제한, 사용자별 rate limit, 비용 상한, 로그의 개인정보 제거, CORS/CSRF 정책을 포함한다.

### 10.3 동기화

로그인과 기기 간 동기화는 별도 프로젝트로 취급한다. 도입 시 이벤트 기반 병합, tombstone, 충돌 정책, 오프라인 큐, 계정 삭제/내보내기를 먼저 설계한다. `updatedAt`이 큰 쪽으로 무조건 덮는 방식은 금지한다.

### Gate G 완료 기준

- localStorage와 IndexedDB가 같은 Repository 계약 테스트를 통과한다.
- 마이그레이션 강제 실패 시 원본이 복원된다.
- 클라이언트 번들·백업·로그에 비밀 키가 없다.
- rate limit과 비용 상한의 통합 테스트가 있다.

## 11. 이번 통합 요청에서 하지 않을 것

- 모든 Gate를 하나의 거대한 PR로 구현하기
- 1,140개 AI 콘텐츠 무검수 일괄 생성
- AI 응답만으로 자동 마스터 판정
- 사용자 승인 없는 새 카드 생성
- 발음 정확도를 STT 문자열 일치율로 단정
- OpenAI Realtime API 선도입
- 저장 Repository 없이 화면에서 localStorage/IndexedDB 직접 접근
- 기존 `vm-*` 원본을 백업 없이 삭제
- API 키를 저장 백업, Git, 클라이언트 로그에 포함

## 12. 공통 자동 테스트

각 Gate의 테스트 외에 다음 회귀 테스트를 계속 유지한다.

1. TOEIC 파트 수가 73/42/29/50이고 합계가 194다.
2. 정적 어휘 팩의 타입과 실제 개수가 화면과 일치한다.
3. 같은 Item의 ID는 배열 순서 변경 후에도 같다.
4. 같은 영문·다른 뜻은 별도 ID다.
5. P3 오답이 P4 또는 내 단어 오답에 섞이지 않는다.
6. 중간 항목 삭제 후 다른 Progress가 유지된다.
7. 모든 Source 합산은 itemId로 중복 제거된다.
8. 모드 호환성은 Item 타입과 예문 존재 여부를 따른다.
9. 모든 화면의 개수는 공통 selector 결과와 같다.
10. 백업 round-trip 후 Item/Progress/Event/연상/세션이 보존된다.
11. 잘못된 가져오기는 기존 데이터를 변경하지 않는다.
12. 사용자 입력과 AI 출력의 XSS payload가 실행되지 않는다.
13. 오프라인·AI 오류에서도 비AI 학습이 가능하다.
14. 날짜/시간대 경계에서 due와 통계가 일관된다.

## 13. 공통 수동 검증 시나리오

1. 새 단어를 입력하고 오늘 신규에 추가해 학습한다.
2. 객관식에서 틀린 뒤 다른 모드로 재출제되는지 본다.
3. 새로고침 후 같은 세션을 이어 완료한다.
4. 다음 날짜를 모의해 due 복습이 등장하는지 확인한다.
5. 어려운 단어의 연상을 생성·수정하고 새로고침한다.
6. 예문을 승인한 뒤 빈칸과 말하기로 학습한다.
7. 마이크 권한 거부와 STT 실패 후 텍스트 대안을 사용한다.
8. 회화를 종료하고 새 표현 일부만 카드로 승인한다.
9. 백업을 내보내고 빈 저장소에 가져와 결과를 비교한다.
10. 모바일 화면과 키보드만으로 핵심 흐름을 완료한다.

## 14. PR과 배포 방식

Gate A~G를 각각 독립 PR로 제출한다. 각 PR에는 다음을 포함한다.

- 변경 목적과 범위, 명시적 제외 범위
- 스키마 변경 및 마이그레이션 설명
- 자동 테스트 명령과 결과
- 수동 검증 시나리오와 결과
- 사용자 화면 변경 스크린샷
- 알려진 제한과 롤백 방법

기능 플래그가 필요한 AI/STT/회화 기능은 기본 비활성으로 병합하고, 오류율·비용·데이터 무결성을 확인한 뒤 활성화한다.

## 15. 최종 완료 정의

아래 조건을 모두 만족할 때 잔여 개발이 완료된 것으로 본다.

- 사용자가 입력한 단어가 명확한 선택을 통해 오늘 신규 큐에 들어간다.
- 오늘 큐가 due 우선, 상한, 중복 제거, 세션 복구 규칙대로 동작한다.
- 모든 결과가 itemId 기반 Progress/StudyEvent에 일관되게 반영된다.
- 연상과 예문은 적응형으로 생성되고 사용자 선택·수정·캐시가 보존된다.
- 단어가 문맥 학습과 말하기로 연결되며 기술 실패가 오답이 되지 않는다.
- AI 회화 결과가 사용자 승인 후에만 새 학습 항목을 만든다.
- 오늘/주간/소스별 숫자가 동일한 selector 정의를 따른다.
- 백업·복원·마이그레이션이 데이터 손실 없이 테스트된다.
- 공개 배포 시 비밀 키가 클라이언트에 없고 비용 통제가 적용된다.
- 핵심 흐름의 자동 테스트, 접근성 점검, 모바일 검증, 롤백 문서가 제공된다.
